# AutoVol — автогромкость звонка и уведомлений по окружающему шуму

Android-приложение, которое периодически замеряет уровень окружающего шума микрофоном и
выставляет громкость звонка и уведомлений: в тишине — минимум, в шуме — ступенчато до максимума.
Это порт отлаженного root-скрипта `reference/autovol.py` (Python, работал через Termux + KernelSU
на OnePlus 15, OxygenOS 16, Android 16). **Логика принятия решений в скрипте проверена на
реальном устройстве — переносить её поведение 1:1, меняется только способ доступа к системе.**

Пользователь (владелец репозитория) общается на русском, работает с телефона. Интерфейс на русском
и английском: строки только в `res/values/strings.xml` (английский, по умолчанию) и
`res/values-ru/strings.xml`, оба обновлять вместе, подписи короткие и без названий прошивок.
Журнал событий (диагностика для автора), README и сообщения коммитов — на русском
(есть README.en.md). Код и комментарии в коде — на английском.

## Доступ к микрофону в фоне и автозапуск
Android отдаёт фоновому приложению тишину вместо звука, а после перезагрузки запрещает стартовать
foreground service типа microphone. Проверено на OnePlus 15 (Android 16): `appops set [--uid]
<pkg> RECORD_AUDIO allow` не держится — служба разрешений сразу возвращает режим UID в `foreground`.
Поэтому:
1. **Базовый (без root):** FGS типа `microphone`, запускается из UI. После перезагрузки —
   уведомление «Нажмите, чтобы возобновить».
2. **Root (KernelSU/Next/SukiSU, Magisk, APatch):** после загрузки/обновления/гибели процесса сервис
   запускается через `su -c am start-foreground-service …` (uid 0 = системный запуск, microphone FGS
   разрешён). Режим UID проверять `unsafeCheckOpRawNoThrow` (не `unsafeCheckOpNoThrow` — тот
   учитывает, на экране ли приложение). Без root-менеджера ничего про root в UI не показывать.
3. **adb** — только как подсказка, ненадёжно на Android 11+. Shizuku (uid shell) работал бы как root.

Всё, что помечено «проверить», проверяется на устройстве пользователя (OnePlus 15, Android 16) —
в конце каждой задачи писать пользователю короткий список, что именно проверить.

## Как устроен цикл (порт `cycle()` из reference/autovol.py)
Один цикл = проверки → замер → решение → установка громкости. Будильник: `AlarmManager`
`setExactAndAllowWhileIdle` (разрешение SCHEDULE_EXACT_ALARM; если не выдано — неточный будильник и
подсказка в UI). На время цикла — PARTIAL_WAKE_LOCK с таймаутом 60 с.

Проверки по порядку (пауза = громкость не трогаем, «синхронизация» сбрасывается, следующий цикл через IDLE):
1. Выключено пользователем → пауза.
2. `ringerMode != NORMAL` (вибро/без звука, слайдер OnePlus) → пауза, **микрофон не включать**.
3. Не беспокоить (`currentInterruptionFilter != ALL`) → пауза (настройка, по умолчанию вкл).
4. Вызов или VoIP: `AudioManager.mode != MODE_NORMAL` → пропуск цикла (без сброса синхронизации), FAST.
5. Внешний вывод звука: в `getDevices(GET_DEVICES_OUTPUTS)` есть BT A2DP/SCO/BLE, проводные,
   USB-аудио → пауза. Это же покрывает Android Auto (в машине всегда BT). Плюс режим автомобиля
   `UiModeManager.currentModeType == CAR` → пауза.
6. Заряд ≤ LOW_BAT и не заряжается → пауза.
7. Ручное изменение громкости: если текущая громкость потока ≠ той, что выставили мы в прошлый раз →
   не трогать OVERRIDE_MIN минут. После любой паузы — синхронизация заново (иначе громкость,
   изменённая в BT/в вибро, будет ложно считаться ручной).
8. Телефон сам воспроизводит звук: `AudioManager.isMusicActive` или непустой
   `activePlaybackConfigurations` → пропуск замера. Проверять И ДО, И ПОСЛЕ записи — звук мог
   начаться во время замера (было реальной причиной ложных максимумов).

Замер: `AudioRecord`, источник `UNPROCESSED` если поддерживается (`PROPERTY_SUPPORT_AUDIO_SOURCE_UNPROCESSED`),
иначе `MIC`; 16 кГц моно PCM16, REC_SEC=2 с, первые 300 мс отбросить. Уровень = RMS в dBFS
(аналог `ffmpeg volumedetect mean_volume`). Цифровая тишина (≤ SILENT_DB = −85) = микрофон заглушён
системой → замер отбросить (не считать «тихой комнатой»!).

Решение (ступени из LEVELS):
- **Повышение:** если ступень замера выше текущей — через CONFIRM_SEC=12 с повторный замер,
  берётся меньший из двух (одиночный всплеск: звук уведомления, стук, шорох — не поднимает).
- **Понижение, «резинка»:** запас m = max(0.5, MARGIN·(1 − (k−1)/(n−1))) для текущей ступени k>0
  (на 1-й ступени MARGIN=3 дБ, на верхней 0.5 дБ). Если ступень(db+m) < k — быстрый повторный
  замер через CONFIRM_SEC; если тоже ниже — сразу вниз до max(обеих ступеней), иначе остаёмся.
- Первый замер после синхронизации применяется сразу.

Громкость: 0% ступени = MIN_VOL (делений, ≥1 — никогда 0, иначе Android переключит в вибро),
100% = максимум, между — пропорционально: `mn + round((hi − mn) · pct/100)`. Потоки RING и
NOTIFICATION. `setStreamVolume` без флага показа UI. Прямо перед установкой повторно проверить
ringerMode и mode (слайдер могли переключить во время замера).

Интервалы: на ступени k>0: `FAST − (FAST − ELEV_INT)·k/n` (выше громкость → чаще проверка →
быстрее возвращается вниз). На ступени 0: FAST, если были изменения за STABLE_MIN, иначе SLOW.

## Автокалибровка
История чистых замеров за CAL_DAYS=7 дней (кольцевой буфер в файле). Когда замеров ≥ CAL_MIN_SAMPLES=300:
тишина = 25-й процентиль, верх = 97-й процентиль, расстояние верх−тишина ограничено [24..40] дБ.
Пороги ступеней: `тишина + CAL_START(8)` … `тишина + span` равномерно. До накопления — ручные LEVELS.
Кнопка «Сбросить калибровку».

## Параметры по умолчанию (из reference/autovol.py, DEFAULTS)
LEVELS `-120:0 -46:25 -39:50 -32:75 -26:100`, MIN_VOL 1, FAST 90, SLOW 150, IDLE 300, ELEV_INT 45,
STABLE_MIN 15, MARGIN 3, CONFIRM_SEC 12, OVERRIDE_MIN 30, REC_SEC 2, SILENT_DB −85, LOW_BAT 15.
Для MediaRecorder-AAC в скрипте dBFS мог отличаться от AudioRecord PCM — калибровка это выровняет.

## Интерфейс
- **Главный экран:** большой переключатель вкл/выкл; статус (текущий дБ, ступень, громкость
  звонка X/Y, причина паузы, состояние калибровки N/300); ползунок «Минимальная громкость».
- **Плитка быстрых настроек** (TileService): вкл/выкл, подпись — текущая громкость или «пауза».
- **Постоянное уведомление** FGS: краткий статус + действие «Пауза 1 ч».
- **Настройки (расширенные):** паузы (DND, внешнее аудио, медиа), интервалы, MARGIN, сброс калибровки.
- **Мастер первого запуска:** микрофон → уведомления → батарея без ограничений → точные будильники →
  фоновый микрофон (adb-команда с кнопкой «Копировать» / Shizuku / root). Показывать, что выдано.
- **Журнал:** последние ~300 событий (как `autovol.log`), кнопка «Поделиться» для отправки автору.

## Сборка и выпуск
- GitHub Actions: `.github/workflows/build.yml` — на каждый push собирать debug APK и выкладывать
  артефакт; на тег `v*` — подписанный release APK в GitHub Releases.

  однострочными командами Termux), как создать keystore и добавить секреты. Подпись не должна
  меняться между сборками — иначе обновление поверх не встанет.
- Gradle wrapper в репозитории. Версии плагинов/библиотек — актуальные стабильные.
- README.md на русском: что делает, скриншоты (позже), установка, выдача фонового микрофона через
  adb/Shizuku/root, ограничения (зелёная точка микрофона при замере — норма).

## Правила работы в этом репозитории
- Пользователь проверяет всё на телефоне. Инструкции для него — короткие, однострочные команды
  (многострочные вставки ломаются в Termux).
- Сначала рабочий минимум (сервис + замер + логика + главный экран), потом плитка, мастер, Shizuku.
- Логику решений (`cycle`, автокалибровка, target_vol) вынести в чистый Kotlin-класс без Android
  зависимостей и покрыть unit-тестами, повторяющими сценарии: всплеск, концерт → тишина, пауза между
  песнями, ручное изменение, BT, вызов, заглушённый микрофон, воспроизведение во время замера.
